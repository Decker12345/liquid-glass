液态玻璃 · 通用实现报告

一份可以直接拿去用的液态玻璃（Liquid Glass）方案：CSS 变量控制外观，JS 引擎负责真实折射， 从「一个按钮」到「整页系统」都能覆盖。本文既是设计说明，也是接线手册。

一、这是什么

液态玻璃不是「半透明白色 + 高斯模糊」。它有三个必须同时成立的要素，缺一个就会退化成毛玻璃或者塑料片：

  • 边缘折射：玻璃是有厚度的，边缘会像透镜一样把背后的画面掰弯、压缩。这是"液"的来源。
  • 极薄的染色：玻璃本体几乎无色（白底 α 通常 ≤ .08），只靠背后透上来的颜色存在。
  • 四边厚度高光：靠 inset 阴影在上下左右各压一条 1~2px 的高光/反光，玻璃的"体"由这四条边勾勒，而不是由白底填充。
一句话判断做对没有：把玻璃放到一片纯白背景上，如果它看起来是一块灰色方块，那就是毛玻璃； 如果几乎看不见、只剩一圈细边，那才是玻璃。

二、原理

浏览器没有原生的"折射"能力，只能靠位移映射（displacement map）近似。整条链路是这样的：

① 圆角矩形 SDF用有向距离场描述玻璃轮廓，得到每个像素到边缘的距离
→
② 生成位移图在倒角带内按 sin 钟形算位移向量，写入 PNG 的 R/G 通道
→
③ feDisplacementMapSVG 滤镜按 R/G 通道偏移像素；R/G/B 三通道用不同 scale 制造色散
→
④ backdrop-filter把滤镜应用到元素背后的实时画面，拖动时逐帧更新

位移为什么是钟形

位移量 d(t) = sin(t·π)，t 从 0（最外缘）走到 1（倒角带内边界）。 两端位移为 0，中段最大 —— 于是玻璃内部完全不变形，只有边缘一圈被掰弯， 正好对应真实玻璃厚边的观感。如果用线性或常量位移，整个面板会像水波纹一样整体扭曲，假的。

为什么每块同尺寸玻璃共用一个滤镜

位移图只跟尺寸 / 圆角 / 倒角宽度有关，与内容无关。所以库里按 宽×高×圆角×倒角 做了两级缓存：同尺寸的 20 个按钮只生成 1 张位移图、1 个 SVG 滤镜。 这是相对"每个元素一套滤镜"的关键优化，也让后期调参只需要改 scale 一个属性。

色散

真实玻璃对不同波长折射率不同，边缘会有极细的彩边。实现方式是把 R/G/B 拆成三路， 分别用 1.04 / 1.0 / 0.96 的倍率位移，最后 screen 混合回去。 倍率不能大：超过 ±10% 就会在大字号边缘出现肉眼可见的橙蓝重影，看起来像坏了而不是像玻璃。

三、三行接入

<link rel="stylesheet" href="css/liquid-glass.css">

<div class="lg lg-card">任意内容</div>

<script src="js/liquid-glass.js"></script>

JS 文件加载后会自动扫描页面里所有 .lg 元素并挂载折射，不需要写任何初始化代码。 不想要折射、只要模糊玻璃的话，不引 JS 就行 —— CSS 本身就是完整可用的降级版本。

想先调参数？ 打开 index.html 调参台， 右侧拖滑块、左侧实时预览，调好点「复制」，把 :root 那段贴进你的项目即可。

四、参数总表

全部参数都是 CSS 变量，可以在 :root、某个容器、或元素自身覆盖（就近优先）。

--lg-brightness亮度1.060.95–1.15

变量含义默认建议范围

引擎参数（JS，不是 CSS 变量）

参数含义默认建议

bezel倒角带宽占短边比例，即"玻璃厚不厚"0.150.10–0.25
dispersion是否开色散true字号小的界面建议关掉
enabled总开关true低端设备/低电量时关
为什么折射强度不做成 CSS 变量？ 因为 feDisplacementMap 的 scale 是 SVG 属性，CSS 变量传不进去， 必须由 JS 写到 DOM 上。外观归 CSS、引擎归 JS，这条边界让两边都能独立替换。 单个元素想改倒角宽度，可以用 data-lg-bezel="0.22" 属性。

指针跟随高光

给元素加 data-lg-light，玻璃表面会有一团跟着鼠标走的反光：

<div class="lg lg-card" data-lg-light>…</div>

实现上是一个 radial-gradient 背景层，位置由 --lg-mx / --lg-my 控制， 强度由 --lg-light-a 控制（默认 0，悬停时 JS 提到 .5）。 因为用的是 background-image 而不是伪元素，所以永远不会盖住文字，也不会影响点击。

六、JS API

方法 / 属性说明
LiquidGlass.supported布尔值，当前浏览器是否支持真折射
LiquidGlass.set({…})改引擎参数，立即生效（改 bezel 会重建位移图）
LiquidGlass.scan(root?)扫描并挂载新插入的 .lg（MutationObserver 已自动处理，一般不用手动调）
LiquidGlass.refresh(el?)重新测量尺寸并重建；不传参数则全量刷新
LiquidGlass.mount(el, {light:true})手动挂载（含可选指针高光）
LiquidGlass.destroy(el)卸载，恢复到纯 CSS 模糊
data-lg="off"标记该元素不参与折射（只保留 CSS 玻璃效果）

七、框架集成

Vue 3 组件

<template>
  <div class="lg" :style="vars"><slot /></div>
</template>

<script setup>
import { computed } from 'vue'
const props = defineProps({ blur: { type: Number, default: 8 } })
const vars = computed(() => ({ '--lg-blur': props.blur + 'px' }))
</script>

React 组件

export default function Glass({ blur = 8, className = '', ...rest }) {
  return (
    <div
      className={'lg ' + className}
      style={{ '--lg-blur': blur + 'px' }}
      {...rest}
    />
  )
}

动态内容

元素尺寸变化后位移图必须重建，否则折射范围会跟实际尺寸错位。库内部用 ResizeObserver 做了 140ms 防抖重建，所以你不需要手动调 refresh。 只有一种情况要手动：元素用了 transform: scale() 之类改变视觉尺寸的变换 —— 这种变化不触发 ResizeObserver。

浏览器真折射纯模糊玻璃说明

Chrome / Edge 76–109✘✔模糊正常，折射退化

旧版 / 不支持 backdrop-filter✘△只剩半透明底色，建议自行加实色兜底

降级是自动且无感的：

  • JS 探测到不支持时，不会给元素加 data-lg-refract，CSS 里的 backdrop-filter 就停在使用 --lg-fn 的模糊版本。
  • 同时给 <html> 加 .lg-no-refract，库自带的补偿样式会把边缘高光和着色各提一点，让"没有折射"的版本也不至于太平。
  • 想自己接管降级外观，写 .lg-no-refract .lg { … } 即可。

九、性能预算

backdrop-filter 的代价主要来自「每一帧重新截取背景 + 做一次模糊」，跟面积成正比。几条经验值：

项目建议原因
同时可见的玻璃元素≤ 12 个每个都是一次独立的背景采样
单个元素面积≤ 屏幕的 40%大面板成本线性上升
blur 半径≤ 20px模糊核变大会成倍增加采样
唯一尺寸数尽量少同尺寸共用位移图与滤镜
列表/长滚动只给吸顶/悬浮元素做玻璃滚动中每帧都要重算
两个常见的性能雷： ① 玻璃里面再套玻璃 —— 嵌套 backdrop-filter 会让内层反复重采样，几乎必掉帧，而且视觉上也糊。 ② 给整个滚动容器加玻璃 —— 应该只给固定的导航/底栏加，内容区用普通背景。

十、常见坑

1. 元素没有内容就看不见玻璃

backdrop-filter 需要有"背景"可采。空 div 高度为 0 时既不采样也不渲染。给个尺寸或内边距。

2. 祖先元素有 overflow: hidden + border-radius

这种情况下玻璃边缘会被裁剪得很难看，尤其是位移把像素推到边界外时。让玻璃元素自己带圆角，别让祖先裁它。

3. 祖先有 filter / transform / will-change

这些都会创建新的层叠上下文或包含块，可能让 backdrop-filter 采样到错误的区域（采到的是祖先的快照而不是页面背景）。 必要时把玻璃元素 position: fixed 提到顶层。

4. <button> 变白

浏览器给表单控件自带 background-color，而 .lg 只设置了 background-image， UA 的灰底会从下面透出来。本库已在 .lg 里写了 background-color: transparent； 自己写玻璃时记得加上。

5. 用 ::after 画高光会盖住文字

这是最容易被忽略的 bug：伪元素铺满整块玻璃画斜向高光，如果没有 pointer-events:none 和正确的 z-index，它会把文字压灰、把按钮点不到。本库的做法是把高光全部并进 background-image， 从根本上消灭这个层级问题。

6. 玻璃叠在纯白背景上会发灰

玻璃透明的本质是"透出背后的东西"。背后是一片白，透出来就是一层灰。 要么在背后放内容（图片、渐变、大字），要么降低 --lg-tint-a、提高 --lg-edge-top，靠边缘而不是靠填充来成形。

调参台里的「正文」「歌词」两个背景就是为这件事准备的：正文是浅色纸张 + 12.5px 两栏密集小字 （最难的一档），歌词是深色大字 + 明暗层次。切到「正文」时舞台会带上 data-tone="light"， 玻璃自动换成"抬边缘、压投影、文字转深色"的一套值——浅底和深底不要共用同一套变量。

7. Safari 需要 -webkit- 前缀

本库两个都写了。自己写的时候漏掉前缀，Safari 会完全没效果（而不是部分效果）。

8. 多个滤镜 id 冲突

本库用 lg-f1、lg-f2… 自增 id 并做了按尺寸复用，不会冲突。手写时记得每个滤镜 id 唯一。

十一、设计建议

什么时候用哪一档

场景推荐配置
导航栏 / 工具栏（文字多）.lg--frost，blur 16–20，tint .18–.22
浮在封面/照片上的按钮.lg--clear，blur 3–6，tint .04
大卡片 / 弹窗.lg，blur 8–12，tint .08，refract 60–80
暗色界面.lg--dark，tint rgb 16 22 38，α .4
要"最玻璃"的展示效果.lg--thin，blur 0，refract 110–130，bezel .2

文字可读性

  • 玻璃上的正文，背后最好有 ≥ 40% 的白色遮罩或深色底；纯折射（blur 0）只适合标题和图标。
  • 模糊半径本质上是"把背景细节抹平"，所以 blur 越大文字越安全，折射越强文字越危险 —— 两者要权衡。
  • 小字号（< 13px）在玻璃上会发灰，加 .lg-text-safe 或提高亮度。

动效

玻璃的"液"感一半来自运动。拖动时把 .is-dragging 加上，高光和投影同时加强， 松开再缓动回去，观感会好很多。注意 transition 只作用在 box-shadow 上， 别给 backdrop-filter 加过渡 —— 那会强制每帧重建滤镜。

十二、跨端限制

平台真折射原因
Web（Chromium）✔完整支持
Web（Safari / Firefox）✘backdrop-filter 不接受 SVG 滤镜引用
微信小程序✘ 小程序 WebView 不支持 backdrop-filter: url(#)，也不支持 getContext('2d').putImageData 生成位移图的完整链路； 只能用 blur + saturate + 四边高光的等价方案（另一份小程序项目里的 .glass 就是这个降级版本的实际落地）。
React Native / Flutter✘只有原生模糊，没有位移映射
结论：液态玻璃在 Web 上可以做到接近原生，在移动端原生容器里目前只能做到"通透 + 厚度"， 做不到"折射"。做设计稿时最好按降级形态出图，避免原生端还原不出来。
